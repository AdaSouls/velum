# Velum — production deployment (API host)

What runs where:

| Piece | Where | Notes |
|---|---|---|
| Compact contract | Midnight **preprod** (for now) | Deployed once from a dev machine with `scripts/deploy.ts` — not from this server |
| Indexer app (`indexer/`) + Postgres | This server (Docker) | Follows the contract via Midnight's public indexer, serves `/api/*` |
| ZK artifacts (`keys/`, `zkir/`) | This server, served by Caddy at `/zk/poap/` | Must match the deployed contract |
| IPFS pinning proxy (`poap-frontend/server`) | This server (optional profile) | Holds the Pinata secret |
| Frontend (`poap-frontend`) | Vercel | Separate repo — see [Frontend on Vercel](#frontend-on-vercel) |
| Proof server | **Open decision** — see [Proof server](#proof-server-open-decision) | |

Caddy terminates TLS (automatic Let's Encrypt) and is the only thing listening publicly:

```
https://$API_DOMAIN/health               → indexer
https://$API_DOMAIN/api/events|tokens|…  → indexer
https://$API_DOMAIN/api/ipfs/*           → ipfs-proxy (optional)
https://$API_DOMAIN/zk/poap/…            → static ZK artifacts
```

Verified locally (podman, 2026-09-24): the image builds, migrations apply, the indexer connects to
the preprod indexer over WebSocket, CORS is applied, and Caddy serves `/health`, `/api/*` and
`/zk/poap/*` (with `Access-Control-Allow-Origin: *`). Also verified against the live preprod
contract (`deployments/preprod.md`): the containerized indexer follows it and `/api/events`
returns its demo event. Live at `https://velum-api.adasouls.io` since 2026-09-25 (Let's Encrypt
TLS issued by Caddy; only 22/80/443 reachable).

## 1. Server preparation (Ubuntu, once)

As a sudo-capable user:

```bash
# Updates + automatic security patches
sudo apt update && sudo apt -y upgrade
sudo apt -y install unattended-upgrades git
sudo dpkg-reconfigure -plow unattended-upgrades

# Docker Engine + compose plugin (official repo)
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"   # log out and back in afterwards

# Firewall: SSH + HTTP/HTTPS only (80 is needed for the ACME challenge and HTTP→HTTPS redirect)
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 443/udp
sudo ufw enable
```

Recommended: SSH key-only login (`PasswordAuthentication no` in `/etc/ssh/sshd_config`).

Note: Docker publishes ports through its own iptables rules, bypassing ufw. That's why only
Caddy has `ports:` in `docker-compose.yml` — never add `ports:` to postgres/indexer.

## 2. DNS

Create an `A` record (and `AAAA` if the server has IPv6) for `$API_DOMAIN` pointing at the
server. Check before the first start — Caddy needs it to obtain the certificate:

```bash
dig +short api.example.com
```

## 3. Code and configuration

```bash
sudo mkdir -p /opt/velum && sudo chown "$USER" /opt/velum
git clone <repo-url> /opt/velum/poap-midnight
cd /opt/velum/poap-midnight/deploy/production
cp .env.example .env
openssl rand -hex 24   # → POSTGRES_PASSWORD
nano .env              # fill in every value
chmod 600 .env
```

`CONTRACT_ADDRESS` comes from `deployments/preprod.md` after `scripts/deploy.ts` runs. The
commit checked out here must be the one the contract was compiled from — the indexer image bakes
in `contracts/src/managed/poap/contract` and parses ledger state with it.

## 4. ZK artifacts

`keys/` is gitignored (100 MB, generated by the compiler), so it doesn't come with the clone.
On the dev machine that has them:

```bash
./deploy/production/sync-zk.sh     # refuses to run on an incomplete set
rsync -az --delete deploy/production/zk/ <user>@<server>:/opt/velum/poap-midnight/deploy/production/zk/
```

On the server, check integrity:

```bash
cd /opt/velum/poap-midnight/deploy/production/zk/poap && sha256sum -c --quiet SHA256SUMS && echo OK
```

## 5. Optional: IPFS proxy

```bash
git clone <poap-frontend-repo-url> /opt/velum/poap-frontend
```

Then in `.env`: uncomment `COMPOSE_PROFILES=ipfs`, set
`FRONTEND_SERVER_DIR=/opt/velum/poap-frontend/server` and `PINATA_JWT` (upload-only scope).

## 6. Start

```bash
cd /opt/velum/poap-midnight/deploy/production
docker compose up -d --build
docker compose ps
docker compose logs -f indexer     # expect: applied 001_init.sql, [gql-ws] connected
curl -s https://$API_DOMAIN/health # {"status":"ok"}
curl -sI https://$API_DOMAIN/zk/poap/keys/claim.verifier | head -1   # HTTP/2 200
```

All services use `restart: unless-stopped`, and Docker starts on boot, so the stack survives
reboots.

## 7. Operations

**Update after a new commit** (same contract):

```bash
cd /opt/velum/poap-midnight && git pull
cd deploy/production && docker compose up -d --build
```

**New contract deployment** (new address — e.g. after a contract change):

1. Deploy with `scripts/deploy.ts` from the dev machine.
2. `git pull` here (matching compiled contract), update `CONTRACT_ADDRESS` in `.env`.
3. Re-run `sync-zk.sh` + `rsync` (step 4).
4. Reset the indexer's database — its cursor and rows belong to the old contract:
   `docker compose down && docker volume rm velum_pgdata && docker compose up -d --build`
5. Update `REACT_APP_MIDNIGHT_CONTRACT_ADDRESS` on Vercel and redeploy the frontend.

**Backups** — the database is fully rebuildable from the chain (the indexer re-syncs from block
0), so backups mainly save re-sync time:

```bash
#!/bin/sh
# /etc/cron.daily/velum-pg-backup  (sudo chmod +x it; no dots in the filename or run-parts skips it)
set -e
docker compose -f /opt/velum/poap-midnight/deploy/production/docker-compose.yml \
  exec -T postgres pg_dump -U velum velum | gzip > /var/backups/velum-$(date +%F).sql.gz
find /var/backups -name 'velum-*.sql.gz' -mtime +14 -delete
```

**Logs**: `docker compose logs --tail=200 -f <service>`.

## Frontend on Vercel

`poap-frontend` is a CRA/CRACO app: framework preset **Create React App**, build command
`npm run build`, output directory `build`. `REACT_APP_*` variables are inlined **at build
time** — changing one on Vercel requires a redeploy.

Environment variables (Production):

| Variable | Value |
|---|---|
| `REACT_APP_MIDNIGHT_NETWORK_ID` | `preprod` |
| `REACT_APP_MIDNIGHT_CONTRACT_ADDRESS` | same as `CONTRACT_ADDRESS` above |
| `REACT_APP_MIDNIGHT_INDEXER_API_URL` | `https://$API_DOMAIN` |
| `REACT_APP_IPFS_API_URL` | `https://$API_DOMAIN` (if the IPFS profile is on) |
| `REACT_APP_MIDNIGHT_PROOF_SERVER_URL` | see below |
| `REACT_APP_API_BASE_URL`, `REACT_APP_BLOCKFROST_*`, `REACT_APP_ADMIN_WALLET_ADDRESSES` | as today |

Required change in `poap-frontend` before this works: `src/midnight/providers.ts` builds the
ZK artifact URL from `window.location.origin` + `/midnight/poap`. Make the base configurable
(e.g. `REACT_APP_MIDNIGHT_ZK_CONFIG_URL=https://$API_DOMAIN/zk/poap`) so it fetches from this
server — its committed `public/midnight/poap/` copy only has 11 of the contract's 18 circuits.
The frontend's SPA routes (e.g. `/share/...`) also need a Vercel rewrite to `index.html`.

## Proof server (open decision)

The frontend proves transactions through `REACT_APP_MIDNIGHT_PROOF_SERVER_URL`, defaulting to
`http://localhost:6300`. That works for developers running one locally; on the public site,
ordinary users don't have one, so **every transaction would fail**. Per the note in
`poap-frontend/src/midnight/providers.ts`, Lace's own proving provider was tried (2026-08-30)
and hit a CORS 403 against the network's remote prover. Options:

1. **Re-test Lace's proving provider** with the current Lace / dapp-connector versions. Best
   outcome: proofs are generated wallet-side and no private data reaches us.
2. **Host a proof server here** (`midnightntwrk/proof-server`, behind Caddy with CORS for the
   Vercel origin). Works immediately, but the proof server receives the circuit's private inputs
   — including each user's contract secret key and private attributes. That contradicts Velum's
   privacy story and makes this server a high-value target; acceptable at most for a demo, with
   users told so.
3. **Require users to run a local proof server.** Keeps privacy, poor UX.
