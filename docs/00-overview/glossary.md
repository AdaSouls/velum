# Glossary

Terms as they are used in this project. Midnight and Compact evolve quickly; where a term has an
official definition, the Midnight documentation is the authority.

## Contract

| Term | Meaning here |
|---|---|
| **Compact** | The language the contract is written in. Compiled by `compactc` into a TypeScript API, ZK circuits and keys. |
| **Ledger** | The contract's public on-chain state: the `export ledger` fields. Anyone can read it. |
| **Circuit** | A function of the contract. An exported circuit that touches the ledger needs a zero-knowledge proof and a transaction; a pure one runs locally. |
| **Entry point** | The name of the circuit a transaction called, as reported by the Midnight indexer (`claim`, `mintTo`, …). |
| **Witness** | A function the *client* implements in TypeScript to hand private data to a circuit. The contract cannot trust its output until an `assert` checks it. |
| **Private state** | Data kept on the user's device and passed to witnesses. In Velum: the secret key and a cache of claimed tokens. |
| **`disclose()`** | The marker Compact requires before a private value may flow somewhere public. A permission, not a publication. |
| **Public transcript** | The list of ledger operations a circuit call performed. It is what the chain sees and applies. |
| **`assert`** | A condition that must hold. If it fails, the call fails locally and no transaction is sent. |
| **Sealed** | A ledger field that can only be written in the constructor (`adminPk`). |

## Cryptography

| Term | Meaning here |
|---|---|
| **Zero-knowledge proof** | Evidence that a circuit was executed correctly on some private inputs, without revealing them. |
| **Prover key / verifier key** | Per-circuit keys produced by the compiler. Clients prove with the prover key; the chain verifies with the verifier key stored in the contract. |
| **ZKIR** | The compiled circuit in ZK intermediate representation, used by the proof server. |
| **Proof server** | The service that builds proofs. It receives the private inputs, so it belongs on a machine the user trusts. |
| **Commitment** | A value that hides some data but binds to it: `persistentCommit(value, rand)`. The data can be revealed later and checked against it. |
| **Opening** | The `(value, rand)` pair behind a commitment. |
| **Merkle tree / root / path** | A tree of hashes. The root commits to all leaves; a path proves one leaf is in the tree without showing the others. |
| **Nullifier** | A value derived from a secret and a context, published to prevent doing something twice, without revealing who did it. Here: `H(secret key, request id)`. |
| **Domain separation** | Starting every hash with a distinct tag so values made for one purpose cannot be reused for another. |

## Velum

| Term | Meaning here |
|---|---|
| **Secret key** (`local_sk`) | A user's 32-byte identity for this contract. Not the wallet's key. |
| **Public key** | `H("adasouls:pk:v1:", secret key)`. Identifies admins, organizers and verifiers. |
| **Holder pseudonym** | `H("adasouls:holder-pk:v1:", secret key, issuer)`. What appears as a token's owner. Different for each organizer. |
| **Issuer / organizer** | Whoever created an event. Identified by their public key. |
| **Event** | Something credentials are issued for. |
| **Token / credential** | One issued credential: a set of ledger rows keyed by a sequential token id. Not a Midnight coin. |
| **Disclosure request** | A question a verifier publishes on-chain so holders can answer it with a proof. |
| **Identity value** | `H("velum:identity:v1:", country, document type, number, salt)`. A credential attribute that ties the credential to one identity document, so a verifier who checked the document can tell the credential is that person's. |
| **Credential update request** | A holder's on-chain request that the issuer re-issue one of their credentials, e.g. after a document was renewed. The ledger holds only a commitment; the content goes to the issuer off-chain. |
| **Re-issue** | `burn` followed by `mintTo` for the same holder. The only way to change a credential's attributes. |
| **Revocation** | A burn by the issuer or the admin, as opposed to a self-burn by the holder. |
| **Maintenance authority** | The key that can replace the contract's circuits in place. |
| **Shell build** | A circuit-less compile of the contract used as the first step of deployment. |

## Chain and indexing

| Term | Meaning here |
|---|---|
| **Block** | A batch of transactions added to the chain. Identified by its height. |
| **NIGHT / DUST** | Midnight's token and the resource used to pay fees. DUST is generated by registered NIGHT. |
| **Midnight indexer** | Midnight's own service that exposes chain data over GraphQL. Velum reads from it. |
| **Velum indexer** | This project's service (`indexer/`) that copies part of the contract's public state into Postgres. |
| **Contract action** | An event from the Midnight indexer about one contract: a deploy, a call or an update. Each carries the contract's full state afterwards. |
| **Cursor / checkpoint** | The Velum indexer's record of where it got to: last block height and last contract state. |
| **State diff** | How the Velum indexer works out what a transaction changed: by comparing the state before and after. |
| **Backfill / reindex** | Processing the contract's history from the beginning to rebuild the database. |
| **Finality** | The point after which a block will not be reverted. |
| **Reorg** | A chain reorganization: blocks that were seen get replaced by others. The Velum indexer has no reorg handling; see [Sync and consistency](../02-indexer/sync.md#finality-and-reorgs). |
| **Eventual consistency** | The API reflects the chain with a delay. A change is visible on-chain before it is visible in the API. |
| **Idempotent** | Safe to apply twice. Processing the same contract action again leaves the database unchanged. |
