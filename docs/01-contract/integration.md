# Integration

How to build the contract, call it from TypeScript, and deploy or connect to it.

## Requirements

| Tool | Version | Notes |
|---|---|---|
| Node.js | 22+ | |
| Compact compiler | 0.31.1 | `compact update 0.31.1`. Pinned in the `compact` script of [`contracts/package.json`](../../contracts/package.json). |
| `@midnight-ntwrk/compact-runtime` | 0.16.0 | |
| `@midnight-ntwrk/midnight-js-*` | 4.1.1 | contracts, proof provider, public data provider, private state provider, ZK config provider, network id |
| `@midnight-ntwrk/ledger-v8` | 8.1.0 | |
| `@midnight-ntwrk/testkit-js` | 4.1.1 | Used by the deployment scripts for wallet and network setup |
| `@midnight-ntwrk/wallet-sdk` | 1.1.0 | |
| `@midnight-ntwrk/dapp-connector-api` | 4.0.1 | Browser only (in `poap-frontend`) |
| Docker or Podman | | For the local devnet and the proof server |

Local devnet images ([`devnet.yml`](../../devnet.yml)):

| Service | Image | Port |
|---|---|---|
| Node | `midnightntwrk/midnight-node:1.0.2` | 9944 |
| Indexer | `midnightntwrk/indexer-standalone:4.3.3` | 8088 |
| Proof server | `midnightntwrk/proof-server:8.1.3` | 6300 |

Install everything from the repository root. `contracts`, `scripts` and `indexer` are npm
workspaces and must share one `node_modules`: two copies of
`@midnight-ntwrk/onchain-runtime-v3` break `instanceof` checks in the WASM bindings. The
`overrides` entry in the root `package.json` pins it for that reason.

```bash
npm install
```

### A proof server is always needed

Proofs are generated by a proof server, and the proof server receives the circuit's private
inputs, including the caller's secret key. Run it on a machine the user controls:

```bash
docker compose -f devnet.yml up -d proof-server    # http://127.0.0.1:6300
```

This is the same for every network. The proof server does not depend on the node or the indexer.
Use `127.0.0.1`, not `localhost`: with rootless Podman the IPv6 lookup can fail the connection.

## What the compiler generates

```bash
cd contracts
npm run compact        # compact compile +0.31.1 compact/poap.compact src/managed/poap/
```

A full build takes a few minutes. Output, under `contracts/src/managed/poap/`:

| Path | Contents | Committed? |
|---|---|---|
| `contract/index.js`, `index.d.ts`, `index.js.map` | The TypeScript API: the `Contract` class, `ledger()`, `pureCircuits`, and the types `Witnesses`, `Ledger`, `ImpureCircuits`, `ProvableCircuits`, `PureCircuits` | Yes |
| `zkir/<circuit>.zkir`, `.bzkir` | Each provable circuit in ZK intermediate representation (text and binary) | Yes |
| `keys/<circuit>.prover`, `.verifier` | Proving and verifying key per provable circuit | **No** (about 100 MB; gitignored) |
| `compiler/contract-info.json` | Compiler, language and runtime versions; every circuit with its arguments and whether it needs a proof | Yes |

Which side uses what:

| Artifact | Used by |
|---|---|
| `contract/index.js` | Every client: runs circuits locally and parses ledger state |
| Prover keys and `.bzkir` | The client, to have the proof server build a proof |
| Verifier keys | Stored on-chain in the contract, one per provable circuit. The network verifies proofs against them. |

**The verifier keys on-chain must match the prover keys clients use.** If they differ, every
call to that circuit fails. This is what an upgrade has to keep in sync.

The build is reproducible: the same source and compiler version give byte-identical keys.
[`scripts/verify-keys.sh`](../../scripts/verify-keys.sh) recompiles into a scratch directory and
diffs it against the checked-out output (`--skip-zk` for a quick check without keys).

### The shell build

```bash
npm run compact:shell --workspace contracts
```

This compiles a copy of the contract with every `export circuit` turned into a plain `circuit`,
using `--skip-zk`. The result has the same ledger and constructor but no provable circuits. It
exists only for deployment, see [Deploying](#deploying). Its output
(`contracts/src/managed/poap-shell/`) is gitignored.

### How the artifacts are distributed

There is no published npm package. Each consumer takes the build output directly:

| Consumer | How it gets the artifacts |
|---|---|
| `scripts/` | Imports `../contracts/src/managed/poap/contract/index.js` and reads keys from `contracts/src/managed/poap/` |
| `indexer/` | Imports the compiled contract (path overridable with `CONTRACT_MODULE_PATH`) to parse ledger state. Needs no keys. |
| API host | [`deploy/production/sync-zk.sh`](../../deploy/production/sync-zk.sh) copies keys and ZKIR to `deploy/production/zk/poap/` with a `SHA256SUMS` file; Caddy serves them at `/zk/poap/` |
| Web app (`poap-frontend`) | Keeps its own copy of the compiled contract and fetches keys and ZKIR over HTTP |

After recompiling, every one of these must be updated together.

## Witnesses in TypeScript

The contract declares two witnesses:

```compact
witness local_sk(): Bytes<32>;
witness store_token(tokenId: Uint<64>, issuerId: Bytes<32>, eventId: Bytes<32>, isSoulbound: Boolean): [];
```

The compiler turns them into a `Witnesses<PS>` type. Each witness receives a `WitnessContext`
(ledger view, current private state, contract address) followed by its Compact arguments, and
returns a tuple `[newPrivateState, returnValue]`.

Type mapping used here: `Bytes<32>` → `Uint8Array`, `Uint<64>` → `bigint`, `Boolean` →
`boolean`, `[]` → `[]`.

The reference implementation is [`contracts/src/witnesses.ts`](../../contracts/src/witnesses.ts):

```ts
import type { WitnessContext } from '@midnight-ntwrk/compact-runtime';
import type { Ledger, Witnesses } from './managed/poap/contract/index.js';

export type PoapPrivateState = {
  secretKey: Uint8Array;
  tokens: Record<string, { tokenId: bigint; isSoulbound: boolean }>;
};

export function createWitnesses(secretKey: Uint8Array): Witnesses<PoapPrivateState> {
  return {
    // Returns the secret key. Private state is passed through unchanged.
    local_sk(context: WitnessContext<Ledger, PoapPrivateState>): [PoapPrivateState, Uint8Array] {
      return [context.privateState, secretKey];
    },

    // Records the token just claimed. Returns nothing to the circuit.
    store_token(context, tokenId, _issuerId, eventId, isSoulbound): [PoapPrivateState, []] {
      const key = Buffer.from(eventId).toString('hex');
      return [
        {
          ...context.privateState,
          tokens: { ...context.privateState.tokens, [key]: { tokenId, isSoulbound } },
        },
        [],
      ];
    },
  };
}
```

Two variants exist:

| Variant | Where the key comes from | Used by |
|---|---|---|
| `createWitnesses(secretKey)` | A value captured when the witnesses are built | Scripts and tests, where the key is derived from a seed |
| `createWitnesses()` reading `context.privateState.secretKey` | The stored private state | The web app, where the key is random and lives in private state |

Rules for a witness implementation:

- `local_sk` must return exactly 32 bytes. A 64-byte value fails with a type error at runtime.
- Always return the private state, changed or not.
- Do not put secrets anywhere but the returned private state.

### Deriving the public identifiers off-chain

`getCallerPk` and `getHolderPk` are exported circuits but need no proof, so they are not part of
the transaction API. Clients compute the same values directly:

```ts
import { persistentHash, CompactTypeVector, Bytes32Descriptor } from '@midnight-ntwrk/compact-runtime';

const pad32 = (s: string) => {
  const out = new Uint8Array(32);
  out.set(new TextEncoder().encode(s));
  return out;
};

// derive_pk(sk)
const callerPk = persistentHash(new CompactTypeVector(2, Bytes32Descriptor), [pad32('adasouls:pk:v1:'), secretKey]);

// holder_pk(issuerId)
const holderPk = persistentHash(new CompactTypeVector(3, Bytes32Descriptor), [
  pad32('adasouls:holder-pk:v1:'),
  secretKey,
  issuerId,
]);
```

Give an organizer `holderPk` for their issuer id, never `callerPk`.

### Pure helpers

The six pure circuits need no context and no network:

```ts
import { pureCircuits } from './managed/poap/contract/index.js';

const eventId = pureCircuits.computeEventId(organizerPk, label);
const commit  = pureCircuits.computePrivateMetadataCommit(value, rand);
const leaf    = pureCircuits.computeAttributeLeaf(eventId, fieldId, value, rand);

// Identity attribute: text inputs right-padded to 32 bytes, salt = 32 random bytes (non-zero).
const idValue = pureCircuits.computeIdentityValue(pad32('ARG'), pad32('national_id'), pad32('12345678'), salt);
```

The other two are `computeCredentialAttrLeaf` and `computeCredentialLeaf`. How the identity
inputs must be normalized is in
[flow 12](circuits.md#12-tie-a-credential-to-identity-documents).

## Running circuits without a network

[`contracts/src/test/poap-simulator.ts`](../../contracts/src/test/poap-simulator.ts) runs the
compiled contract in memory with `compact-runtime` only: no node, no proof server, no proofs. It
is the fastest way to see a circuit's behaviour.

```ts
const sim = new PoapSimulator(ADMIN_SK);                    // deploys; ADMIN_SK becomes admin
const eventId = sim.asUser(ISSUER1_SK).createEvent(label, 100n, 0n, true);
sim.asUser(USER1_SK).claim(eventId, true);
const ledger = sim.getLedger();                             // typed view of public state
```

`asUser` switches the secret key and private state while keeping the shared public state.

## Providers

A real call needs six providers. The two clients in this project configure them differently.

| Provider | Role | Scripts (Node) | Web app (browser) |
|---|---|---|---|
| Private state | Stores `PoapPrivateState` | LevelDB store `poap-deploy-state` / `poap-upgrade-state` | LevelDB provider in the browser, password-encrypted, scoped to the wallet's shielded address |
| ZK config | Supplies prover/verifier keys and ZKIR | `NodeZkConfigProvider` reading `contracts/src/managed/poap/` | `FetchZkConfigProvider` fetching `<base>/keys` and `<base>/zkir` over HTTP |
| Proof | Sends the circuit and private inputs to the proof server | HTTP client to `http://127.0.0.1:6300` | HTTP client to `REACT_APP_MIDNIGHT_PROOF_SERVER_URL` (default `http://localhost:6300`) |
| Public data | Reads contract state and watches for transactions via the Midnight indexer | Indexer URLs from the network config | Indexer URLs from the wallet's `getConfiguration()` |
| Wallet | Balances the transaction (adds the DUST fee) | A wallet built from `MN_TEST_WALLET_SEED` | The extension's `balanceUnsealedTransaction` |
| Midnight | Submits the transaction | Same wallet | The extension's `submitTransaction` |

In the scripts, `initializeMidnightProviders` from `testkit-js` builds all six from a wallet and
an environment configuration:

```ts
const providers = initializeMidnightProviders<PoapCircuits, PoapPrivateState>(wallet, envConfig, {
  privateStateStoreName: 'poap-deploy-state',
  zkConfigPath: ZK_CONFIG_PATH,
});
```

In the browser, the wallet extension is discovered under `window.midnight` and connected with
`connect(networkId)`. Compatible wallets at the time of writing: Lace (`io.lace.wallet`) and 1am
(`com.midnight.1am`). The network id passed to `connect` must match the network the wallet is
set to, or the wallet rejects the connection.

Set the network id before any contract operation:

```ts
import { setNetworkId } from '@midnight-ntwrk/midnight-js-network-id';
setNetworkId('preprod');   // or 'undeployed' for the local devnet
```

## Connecting to a deployed contract

```ts
import { CompiledContract } from '@midnight-ntwrk/midnight-js-protocol/compact-js';
import { findDeployedContract, submitCallTx } from '@midnight-ntwrk/midnight-js-contracts';
import { Contract } from '../contracts/src/managed/poap/contract/index.js';
import { createWitnesses, type PoapPrivateState } from '../contracts/src/witnesses.js';

const compiled = CompiledContract.make('PoapContract', Contract).pipe(
  CompiledContract.withWitnesses(createWitnesses(secretKey)),
  CompiledContract.withCompiledFileAssets(ZK_CONFIG_PATH),
);

const contract = await findDeployedContract(providers, {
  compiledContract: compiled,
  contractAddress,
  privateStateId: 'poapPrivateState',
  initialPrivateState: { secretKey, tokens: {} },   // first connection only
});

// Either through the handle…
await contract.callTx.claim(eventId, true);

// …or directly:
await submitCallTx(providers, {
  compiledContract: compiled,
  contractAddress,
  privateStateId: 'poapPrivateState',
  circuitId: 'createEvent',
  args: [label, 100n, 0n, true, 'ipfs://…', new Uint8Array(32), new Uint8Array(32)],
});
```

`findDeployedContract` checks that the verifier keys on-chain match the local build and throws
if any circuit is missing or different. Pass `initialPrivateState` only when no private state
exists yet under that id.

Reading public state needs no wallet and no proof:

```ts
import { ContractState } from '@midnight-ntwrk/compact-runtime';
import { ledger } from '../contracts/src/managed/poap/contract/index.js';

const state = await providers.publicDataProvider.queryContractState(contractAddress);
// In Node, round-trip through compact-runtime's own class first; passing the provider's
// object straight to ledger() fails with "expected instance of ChargedState".
const view = ledger(ContractState.deserialize(state.serialize()).data);
view.events.lookup(eventId);
```

For application queries (events, tokens by owner, disclosure requests, credential requests,
credential update requests), use Velum's own indexer
REST API in [`indexer/`](../../indexer/) instead of walking the ledger.

### Building Merkle paths

| Path | How to get it |
|---|---|
| Credential path (`credPath`) | `ledger.credentials.pathForLeaf(tokenId, computeCredentialLeaf(eventId, holderPk, credAttrRoot))`, against the latest state |
| Attribute path, set path | Built off-chain by whoever built the tree. See `buildMerklePath` in the simulator for the exact hashing. |

A path argument is an object `{ leaf: Uint8Array, path: { sibling: { field: bigint }, goes_left: boolean }[] }`
with exactly as many entries as the tree's depth (8, 16 or 20).

## Deploying

```bash
# Local devnet
docker compose -f devnet.yml up -d
npm run compact --workspace contracts
npm run compact:shell --workspace contracts
npx tsx scripts/deploy.ts

# Preprod
docker compose -f devnet.yml up -d proof-server
MN_TEST_ENVIRONMENT=preprod MN_TEST_WALLET_SEED=<hex seed> npx tsx scripts/deploy.ts
```

| Variable | Meaning |
|---|---|
| `MN_TEST_ENVIRONMENT` | `undeployed` (default, local devnet), `preprod`, `preview`, `qanet`. Network URLs come from `testkit-js`. |
| `MN_TEST_WALLET_SEED` | Hex seed of a funded wallet. Required off the local devnet, where a pre-funded genesis wallet is used. Get an address to fund with [`scripts/wallet-info.ts`](../../scripts/wallet-info.ts). |
| `DUST_SYNC_TIMEOUT_MIN` | How long to wait for the wallet's DUST sync (default 180) |
| `SKIP_DEMO_EVENT` | Set to `1` to leave the contract empty (no demo event). Used for the public preprod deployment. |

What the script does:

1. Builds the wallet, registers its NIGHT for DUST generation if needed, and waits until it can
   pay fees. On preprod the first run replays the network's whole DUST history, which took
   1.5–2 hours. Progress is saved to `.wallet-state/`, so later runs only catch up.
2. **Deploys the shell build.** A deployment carrying all 22 verifier keys is rejected by the
   node for exceeding the block weight limit, so the script deploys the circuit-less shell first.
3. **Inserts each circuit's verifier key** in its own transaction, signed by the contract's
   maintenance authority. If the run is interrupted here, finish it with
   `scripts/upgrade.ts --apply` against the same address (it inserts the missing circuits);
   running `deploy.ts` again would deploy a new shell.
4. Checks the result against the full build with `findDeployedContract`.
5. Creates a demo event, unless `SKIP_DEMO_EVENT=1`.
6. Writes `deployments/<network>.md` and `.env.<network>.local` (`.env.local` for the devnet).
   The env file contains the admin seed and is gitignored.

Two keys are derived from the deploying wallet's seed:

| Key | Derivation | Controls |
|---|---|---|
| Contract secret key (`local_sk`) | The seed itself if 32 bytes, else `SHA-256(seed)` | The admin role (`adminPk`) |
| Maintenance authority signing key | `SHA-256(seed ‖ "poap-maintenance-authority")` | Inserting and removing verifier keys, i.e. upgrades |

Both are deterministic on purpose: losing a randomly sampled maintenance key between the shell
deployment and the last insert would freeze the contract half-deployed.

## Upgrading in place

[`scripts/upgrade.ts`](../../scripts/upgrade.ts) replaces circuits at the same address, keeping
the ledger state.

```bash
CONTRACT_ADDRESS=<addr> npx tsx scripts/upgrade.ts            # plan only, no wallet needed
CONTRACT_ADDRESS=<addr> npx tsx scripts/upgrade.ts --apply    # swap the keys that differ
```

It compares each local verifier key with the one on-chain and, with `--apply`, removes and
re-inserts the ones that differ.

| Change | Upgrade or new deployment? |
|---|---|
| Comments, formatting | Neither. The keys do not change. |
| Circuit logic, with unchanged `ledger` declarations and circuit signatures | Upgrade |
| Any change to `ledger` declarations or the types stored in them | New deployment |
| Changing how ids are derived (`event_key`, `holder_pk`, …) | Upgrades technically, but orphans existing data |

A quick test for "ledger and signatures unchanged": `contract/index.d.ts` has no diff.

After `--apply`, clients must get the new build at once: run `sync-zk.sh`, copy the artifacts to
the API host and ship the matching frontend. Until they do, calls to the swapped circuits fail.
The indexer database needs no reset. See
[`deploy/production/README.md`](../../deploy/production/README.md) for the runbook.
